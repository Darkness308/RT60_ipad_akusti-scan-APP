2. Fatale Test-Lücke: Leere Messungen = OK

DIN18041Tests.swift:139-147 + RT60Evaluator.swift:51-55 
// DIN18041Tests.swift:139-147
func testEmptyMeasurements() {
    let deviations = RT60Evaluator.evaluateDINCompliance(
        measurements: [],  // LEER!
        roomType: .a3Education,
        volume: 150.0
    )
    XCTAssertTrue(deviations.isEmpty)
    XCTAssertEqual(RT60Evaluator.overallCompliance(deviations: []),
                   .withinTolerance)  // ⚠️ FATAL
}

// RT60Evaluator.swift:51-55 — ROOT CAUSE
public static func overallCompliance(deviations: [RT60Deviation]) -> EvaluationStatus {
    let nonCompliantCount = deviations.filter { $0.status != .withinTolerance }.count
    if nonCompliantCount == 0 {  // ← EMPTY ARRAY: count = 0
        return .withinTolerance   // ← BUG: Returns "compliant" for EMPTY!
    }
    // ...
}
Problem: "Nicht gemessen" wird als "withinTolerance" bewertet!
Ursache: Vacuous-Truth-Bug — 0 von 0 nicht-konform = "alle konform".
Konsequenz: Ein System ohne Messungen wird als DIN-konform eingestuft.

3. Zirkuläre Tests (Selbst-Validierung)

DIN18041Tests.swift:89-101 — Test erstellt Measurements aus Targets, testet dann ob sie "withinTolerance" sind:

// ↑ Measurements = exakt die Zielwerte!

let deviations = RT60Evaluator.evaluateDINCompliance(...)

6. Fehlende Canary-Patterns

Nicht gefunden:
  • Keine Sentinel-Werte zum Erkennen von Regressionen
  • Keine Boundary-Canaries (was soll SCHEITERN?)
  • Keine Inverse-Tests (falsche Eingaben → erwarteter Fehler)
  • Keine Golden-File-Vergleiche mit externen Referenzdaten

Empfohlene Canary-Implementierung

// CANARY: Dieser Test MUSS fehlschlagen wenn Sabine-Konstante geändert wird
func testSabineConstantCanary() {
    let CANARY_SABINE = 0.161
    let result = RT60Calculator.calculateRT60(volume: 100, absorptionArea: 10)
    XCTAssertEqual(result, CANARY_SABINE * 100 / 10, accuracy: 0.0001,
        "CANARY BREACH: Sabine constant changed! Was: \(CANARY_SABINE)")
}

// CANARY: Leere Messungen DÜRFEN NICHT "withinTolerance" sein
func testEmptyMeasurementsCanary() {
    let result = RT60Evaluator.overallCompliance(deviations: [])
    XCTAssertNotEqual(result, .withinTolerance,
        "CANARY BREACH: Empty measurements must not be within tolerance!")
}

// CANARY: Inverse — unplausible Werte müssen erkannt werden
func testImplausibleValuesCanary() {
    // RT60 of 100 seconds is physically impossible for normal rooms
    let deviations = RT60Evaluator.evaluateDINCompliance(
        measurements: [RT60Measurement(frequency: 500, rt60: 100.0)],
        roomType: .a3Education,
        volume: 150.0
    )
    XCTAssertEqual(deviations.first?.status, .tooHigh,
        "CANARY BREACH: RT60=100s must be tooHigh!")
}

// CANARY: DIN A3 bei 200m³ muss T_soll ≈ 0.566s liefern
func testDINA3GoldenValueCanary() {
    let tSoll = RoomType.a3Education.targetReverberationTime(volume: 200)
    XCTAssertEqual(tSoll, 0.566, accuracy: 0.005,
        "CANARY BREACH: A3@200m³ golden value changed!")
}

9. Empfehlungen

  1. Sabine-Konstante parametrisieren — Temperatur/Feuchte als Eingabe
  2. Leere Messungen als "notEvaluated" behandeln — nicht als "withinTolerance"
  3. Externe Referenzdaten laden — DIN-Koeffizienten aus JSON/YAML statt hardcoded
  4. Canary-Tests implementieren — Regressionen aktiv erkennen
  5. Golden-File-Tests — Vergleich gegen bekannte Referenzwerte
  6. DIN 18041:2016-03 manuell verifizieren — Norm beschaffen und prüfen
